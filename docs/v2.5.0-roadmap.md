# Relay Console v2.5.0 roadmap

Status: planned v2.5 scope implemented and reciprocally reviewed. The atomic
release-candidate migration is complete on `develop/v2.5.0` and awaits final
peer audit before merge, tag, or publication.

## Product goal

Make Relay Console useful to more people without creating second-class
language modes. German and Arabic must cover the same interface, prompt,
export, recovery, accessibility, and privacy surfaces as English, French, and
Spanish.

The release theme is **Relay across languages**.

## Committed scope

### Complete German support

- Translate every registered interface key.
- Generate every turn kind in German without modifying user-entered content.
- Parse one strict `RANGLISTE:` line for ballots.
- Localize transcript exports, review packets, imports, recovery, storage, and
  accessibility labels.

### Complete Arabic support

- Translate the same complete catalog as every other language.
- Set the document language and right-to-left direction from explicit locale
  metadata.
- Use logical layout edges and automatic direction for user-entered text.
- Keep technical progress geometry predictable while its visible labels follow
  the Arabic reading direction.
- Generate every turn kind in Arabic and parse one strict `الترتيب:` ballot
  line.

### Independent language choices

- Preserve separate interface and prompt language selectors.
- A German interface may generate Arabic prompts, and an Arabic interface may
  generate German prompts.
- Preserve the saved language choices in sessions and presets.
- Fall back to English for unsupported or legacy locale values.

## Quality boundary

- Every language catalog must have the same keys and placeholders.
- User questions, names, roles, answers, and forwarded text must remain
  byte-for-byte unchanged by translation and export logic.
- Existing session formats and all released artifacts must remain compatible.
- The single-file, offline, local-storage, and no-network privacy boundary must
  remain unchanged.
- Active product, planning, test, and release text must contain no Unicode em
  dash character.
- Desktop and narrow-screen browser checks must cover both German and Arabic.
- Arabic must be checked for clipping, ordering, mixed-direction content, focus,
  and horizontal overflow.
- German and Arabic wording must receive independent review before release.

## Explicitly out of scope

- No partial locale that covers only the setup screen.
- No machine translation service, remote font, analytics, or new network
  permission.
- No automatic chatbot integration or change to the manual handoff model.
- No migration of the live `index.html`, checksum manifest, tag, or release
  assets until the release-candidate gate.

## Release-candidate gate

Completed before the atomic migration:

1. Current and historical suites passing through the same discovery command as
   CI.
2. Complete five-language catalog and placeholder parity.
3. German and Arabic prompt, ballot, transcript, review-packet, import, and
   persistence evidence.
4. Live desktop, 390-pixel, and 320-pixel browser checks with no console error
   or horizontal overflow.
5. Independent peer review with permission to improve code, translations,
   tests, and documentation on the development branch.
6. A final check that all v2.4 release surfaces remain unchanged.

The migration renamed the artifact, moved live-page and checksum ownership into
the v2.5 suite, extended the ordered manifest to ten artifacts, and updated the
public copy together. Merge, tag, release, and upload remain separate and must
wait for final peer review and Youssef's explicit approval.
