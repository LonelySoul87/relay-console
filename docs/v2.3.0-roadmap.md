# Relay Console v2.3.0 roadmap

Status: release candidate ready for review on `develop/v2.3.0`.

## Product goal

Make reusable Relay Console workflows portable between browsers and computers,
and make independent ChatGPT and Claude review handoffs safer and clearer.

## Required scope

### 1. Portable preset bundles

- Export saved presets as a versioned JSON bundle.
- Import bundles without including a question, answers, prompts, forwarded
  context, session nonces, or other session data.
- Validate every imported field before it reaches storage or a generated
  prompt.
- Preserve valid v2.2-era presets already stored in the browser.
- Keep imports atomic and never silently overwrite a preset with the same name.

### 2. Preset hardening and repairs

- Route existing preset loading through the same validator used by imports.
- Accept only HTTP and HTTPS participant URLs from preset data.
- Bound imported roles, URLs, names, roster size, custom steps, and rounds.
- Persist the complete loaded setup, including its recipe.
- Use one round as the consistent fallback.
- Clear a quick-start status message when the setup is changed.

## Included if verification remains strong

### 3. Narrow review packet

- Export a Markdown packet intended for independent review by ChatGPT or
  Claude.
- Include the question, configuration, participants and roles, captured
  answers, context decisions, stale and review warnings, and ballot results.
- Exclude generated prompts so packet size remains linear in the session.
- Use a packet-specific marker and neutralize both packet and session markers
  inside quoted material.
- Follow the generated-prompt language, not the interface language.
- Warn clearly that trimming is not redaction and that captured answers remain
  in the packet.

## Explicitly out of scope

- No fourth quick start. The existing Challenge a decision workflow already
  covers propose, audit, repair, and judge.
- No generated prompts inside review packets.
- No review-packet import path.
- No sharing URLs, QR codes, APIs, backend, remote storage, or dependencies.
- No new language pack in this release.
- No edits to earlier versioned artifacts or tags.

## Quality boundary

- Keep the application one standalone offline HTML file.
- Preserve v1.x and v2.x session compatibility.
- Preserve English, French, and Spanish key and placeholder parity.
- Add a dedicated v2.3 regression suite and wire it into every CI path.
- Expand the no-em-dash guarantee to every tracked active Markdown file.
- Complete wide and narrow browser verification before publication.
- Use Claude Code for an independent read-only implementation audit before the
  release candidate is approved.

## Release migration gate

Before the draft becomes the release candidate:

- Move the `index.html` byte-identity assertion from the v2.2 suite into the
  v2.3 suite and update it to compare against `relay-console-v2.3.0.html`.
- Move the strict checksum-manifest assertions into the v2.3 suite and extend
  the ordered file list to eight releases, ending with v2.3.0.
- Remove those two release-current assertions from the v2.2 suite only after
  the v2.3 replacements pass.
- Update `index.html`, `SHA256SUMS.txt`, release notes, and the immutable release
  artifact together, then verify their exact bytes before tagging.
- Rename the draft artifact to `relay-console-v2.3.0.html`, set the embedded
  version to `2.3.0`, and retarget every draft-bound v2.3 test assertion.
- Extend the active no-em-dash scan to user-visible SVG prose and the remaining
  repository-root text files.
