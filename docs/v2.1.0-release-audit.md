# Relay Console v2.1.0 release audit

Audit date: 2026-08-23

Branch: `release/v2.1.0`

Artifact: `relay-console-v2.1.0.html`

## Result

**PASS for release.** Final naming has been applied, all automated and
interactive checks pass, and the owner authorized the complete publication
workflow after reviewing the audit result.

The release keeps the project boundary intact: one standalone HTML file, zero
runtime dependencies, no backend, no API keys, no remote assets, no trackers,
and no programmatic network calls.

## Scope completed

- Added complete English and French interface catalogs.
- Added separate interface-language and prompt-language controls.
- Persisted both choices and detected the browser language on first use.
- Localized every built-in recipe and prompt kind: answer, blind, debate,
  revise, ballot, and synthesis.
- Localized setup, participant and custom-plan editors, run coaching, lane,
  scorecard, completion statistics, alerts, confirmations, placeholders,
  titles, accessible names, and Markdown transcript exports.
- Preserved user questions, pasted answers, participant names, custom roles,
  and edited forwarded context verbatim.
- Added French `CLASSEMENT:` ballot parsing alongside strict English
  `RANKING:` parsing.
- Preserved old-session compatibility and added safe language defaults.
- Expanded continuous regression checks to cover v2.0 and v2.1 together.

## Problems found and fixed during hands-on testing

1. Two translated rich-text labels could display an undefined value because a
   dataset property name did not match its HTML attribute. The property mapping
   and regression coverage were corrected.
2. Changing only the interface language could make the prompt language follow
   it after a reload on first use. Both preferences are now persisted
   independently as soon as their initial values are resolved.
3. Recipe names could briefly return to English after a French reload. Startup
   now rebuilds recipe choices after locale resolution.
4. Automatically suggested roles could become frozen as if the user had typed
   them. Explicit and suggested roles are now distinguished, including a safe
   compatibility rule for older saved data.
5. Copy-only synthesis showed an external-link arrow even though it opened no
   website. The arrow now appears only when an actual destination will open.
6. French score labels used one plural form for every value. Singular and plural
   point labels are now handled correctly in the interface, prompts, and export.
7. French ballot prompts and the unparsed-ballot example still requested the
   English `RANKING:` keyword. They now consistently request the supported
   French `CLASSEMENT :` form; English `RANKING:` input remains compatible.

## Publication verification

- The final artifact and `index.html` must be byte-identical.
- GitHub checks must pass on the release pull request before merge.
- The `v2.1.0` tag must point to the merged `main` commit.
- The GitHub release asset must match the repository checksum.
- The public landing page and latest-release download must resolve correctly.

Direct `file://` navigation could not be automated because the controlled
browser blocks local-file URLs by policy. The same standalone file was tested
over a local HTTP server, while the no-dependency, no-remote-resource, and CSP
properties were verified directly from the file and by regression tests.
