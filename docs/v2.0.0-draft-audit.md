# Relay Console v2.0.0-draft Release-Candidate Audit

Date: 2026-08-23

Artifact under review: `relay-console-v2.0.0-draft.html`

## Verdict

**PASS as a release candidate.** The four original release blockers and all
smaller findings from the first audit have been fixed. Two additional edge-case
regressions found during the retest were also fixed and added to the automated
suite. Final naming, tagging, and publishing remain separate release actions.

## Automated verification

- The zero-dependency Node suite passes all 20 checks with:
  `node --test tests/relay-console-v2.test.mjs`.
- The suite executes the embedded application script in a minimal browser
  environment and covers:
  - strict explicit ballot parsing and rejection cases;
  - exact-permutation Borda validation;
  - all six recipe turn structures;
  - ballot, reviewer, custom synthesis, and judge role propagation;
  - ballot and prompt staleness;
  - durable parsed and manually corrected ballots;
  - excluded-context revision behavior;
  - unchanged-answer stale recovery;
  - import replacement protection and participant limits;
  - duplicate imported ID normalization;
  - preset save/load/delete privacy boundaries;
  - accessible-label hooks and the standalone privacy boundary;
  - four real legacy fixtures, including v1.0 and v1.8.2 sessions.
- `.github/workflows/v2-regression.yml` runs the same suite on relevant pushes
  and pull requests without adding runtime dependencies to the application.
- Embedded JavaScript parses successfully and `git diff --check` passes.

## Interactive browser verification

- All six recipes passed end to end with the expected turn counts:
  Debate, Blind + synthesize, Ballot panel, Draft -> Critique -> Revise,
  Red team vs Blue team + judge, and Custom plan.
- Debate prompts received earlier discussion through nonce-marked quote fences.
  Blind prompts did not leak earlier blind answers.
- DCR revision prompts contained the original draft and every critique.
- Built-in Blue, Red, Reviser, Reviewer, and Judge roles appeared in the UI and
  in their generated prompts. A custom `Final arbiter` synthesis role also
  appeared in both places.
- Ballot testing verified that prose, a ranking without `RANKING:`, partial
  rankings, duplicate labels, and ambiguous multiple lines are rejected.
  Exact rankings parse, persist across reload, and can be visibly corrected.
- Manual corrections survive reload and can be reparsed deliberately. The
  unchanged default order can be confirmed without a swap workaround.
- Four confirmed ballots produced a Borda tally in the synthesis prompt and in
  the exported Markdown transcript.
- Changing an earlier ballot marked both the recorded synthesis and a manually
  edited synthesis prompt stale. Regeneration used the new tally, and an
  explicit unchanged save cleared the answer warning.
- Context trimming, exclusion, reset-to-full, review warnings, edited-prompt
  regeneration, and deliberate keep-edited behavior all passed.
- Resume, keyboard copy, Ctrl+Enter advance, Skip, early wrap-up, reopen, tidy
  spacing, synthesis-runner selection, list/grid views, three response formats,
  theme cycling, final-answer copy, and Markdown copy passed.
- Participant add, remove, reorder, provider menu, Escape-to-close, custom-step
  add/reorder/remove, and unique accessible names passed.
- Final-candidate browser console inspection found no errors or warnings.

## Files, compatibility, and responsive behavior

- The actual file picker imported a real v1.8.2 session and a saved v2 ballot
  session. Turns, saved answers, forward-curation metadata, staleness, tally,
  and synthesis content remained available.
- Session JSON and Markdown downloads were created and parsed successfully.
- The standalone file opened directly in Microsoft Edge over `file://` with the
  complete setup interface and accessible control names.
- A live 502-pixel-wide Edge window activated the narrow-screen rules. Participant
  URL and role fields stacked cleanly, controls stayed inside the viewport, and
  no horizontal page clipping was visible.

## Security and privacy

- The Content Security Policy keeps network, frames, objects, workers, media,
  fonts, forms, and base-URL changes disabled.
- No external script or stylesheet is loaded, and no `fetch`, XHR, beacon,
  WebSocket, EventSource, worker, or service-worker path exists.
- User and imported text is rendered through text nodes rather than HTML sinks.
- Provider pages open only after the user's Copy & open action, accept only an
  HTTP(S) URL, and use `noopener`.
- No credential or secret was found in the artifact.
