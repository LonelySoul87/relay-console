# Relay Console v2.5.0 release-candidate audit

Audit date: 2026-09-02

Branch: `develop/v2.5.0`

Artifact: `relay-console-v2.5.0.html`

## Result

**PASS for peer release-candidate review.** The final naming and integrity
migration are complete. The candidate is ready for independent review before
any merge, tag, GitHub release, or public upload.

Relay Console remains one standalone HTML file with no runtime dependencies,
backend, API keys, remote assets, trackers, or programmatic network calls.

## Scope completed

- Added complete German and Arabic interfaces, generated prompts, ballot
  markers, transcripts, review packets, imports, recovery, storage, and
  accessibility copy alongside English, French, and Spanish.
- Added explicit right-to-left Arabic layout while preserving automatic text
  direction for user questions, names, roles, answers, and addresses.
- Hardened mixed-direction ballot parsing, visible ranking safety, Arabic lane
  geometry, plural categories, reduced-platform plural fallback, and localized
  synthesis headings.
- Corrected high-confidence Arabic and German grammar and terminology findings
  through an evidence-backed language audit.
- Added privacy-aware public feedback forms and an in-app route that never
  includes relay data or query parameters.
- Corrected light-theme text contrast in automatic and manually selected modes,
  defined two missing style tokens, and covered all four palette blocks.

## Reciprocal development and review

ChatGPT and Claude Code both implemented changes, regression tests, and
documentation on the development branch, then repeatedly audited and falsified
one another's work. The final palette round caught a split between automatic
and manually selected light mode that one clean review had missed. The fix at
`ed71adf` was then verified through all four palette blocks, the real theme
control, and six deliberate regressions.

The release-candidate migration followed that review. It moved current-release
integrity ownership from v2.4 to v2.5 in the same change, so the live-page and
checksum guarantees never disappear from the test history.

## Browser and accessibility evidence

Live desktop, 390-pixel, and 320-pixel checks covered German, Arabic,
mixed-direction input, wrapping, clipping, horizontal overflow, and the browser
console. The actual theme control was driven through automatic, dark, and light
states. Fresh loads of manually selected light and dark mode produced no text
contrast failure.

The final release bytes were served again after migration. At 320 by 700 CSS
pixels, Arabic set the document language and direction correctly, the page and
updated landing page had no horizontal overflow, the localized feedback link
was present, and the browser console remained free of warnings and errors. The
manually selected light palette persisted across a reload with the corrected
warning, success, peer-ranking, and link colors.

The following human checks are not claimed as completed:

- Fluent-human Arabic wording review.
- Fluent-human German wording review.
- A listening session with NVDA or VoiceOver.
- A tap and feel pass on a physical touchscreen.

Automated and browser evidence covers the underlying catalog, grammar, layout,
focus, naming, live-region, keyboard, target-size, and reflow behavior. Per the
project acceptance decision, the four human checks remain post-release feedback
areas rather than release blockers.

## Integrity falsification

Eight deliberate failures were introduced one at a time on an isolated copy.
All eight were caught: a changed `index.html`, a false v2.5 digest, a false
historical digest, a missing tenth manifest entry, reordered manifest entries,
a changed release artifact, CRLF manifest bytes, and a trailing blank line.

The isolated copy was removed after the checks. The candidate files were never
modified for falsification.

## Publication boundary

This audit does not merge the branch, create a tag, publish a GitHub release, or
verify any public download. The candidate commit must pass GitHub Actions and an
independent peer release-candidate review. The final `v2.5.0` tag must point to
the merged `main` commit, and the public asset, release checksum attachment,
repository artifact, and live Pages deployment must all match the checksum
above.
