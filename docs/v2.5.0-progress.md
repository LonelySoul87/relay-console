# Relay Console v2.5.0 progress

## Baseline

- Created `develop/v2.5.0` in an isolated worktree from the published v2.4.0
  merge commit `2b2a37e`.
- Preserved `relay-console-v2.4.0.html`, `index.html`, and the checksum manifest.
- Created `relay-console-v2.5.0-draft.html` and a dedicated v2.5 regression
  suite.

## Language implementation checkpoint

- Added German and Arabic as complete interface and prompt languages.
- Each of the five catalogs contains the same 431 keys with identical
  placeholder sets.
- Added explicit `ltr` and `rtl` locale direction metadata. Arabic updates both
  the document language and direction without changing the selected prompt
  language.
- Converted direction-sensitive styling to logical start and end properties.
- Added automatic direction to user-entered questions, participant names,
  roles, prompts, answers, transcript text, and forwarded-context edits. Web
  addresses remain left-to-right.
- Added strict German and Arabic ballot markers without weakening the exact
  permutation validator.
- Added German and Arabic transcript export coverage and language persistence
  coverage.

## Current verification

- The v2.5 suite passes 123 checks with no failures or skips.
- Automatic discovery passes all 354 current and historical checks with no
  failures or skips.
- Catalog parity, declarative keys, placeholders, all prompt kinds, ballot
  parsing, transcript export, session metadata, recovery, storage, accessible
  names, privacy, and no-em-dash coverage pass.
- User-entered content remains unchanged in German and Arabic prompt and export
  tests.
- Live browser checks pass at desktop, 390-pixel, and 320-pixel widths for both
  German and Arabic. Neither language produces horizontal page overflow,
  clipping, or a browser warning or error.
- The Arabic interface sets `lang="ar"` and `dir="rtl"`. Empty Arabic fields
  start from the right, Arabic input remains right-to-left, English input
  switches left-to-right, and web addresses remain left-to-right.
- The browser pass caught and fixed Arabic placeholder alignment before this
  checkpoint. A regression assertion now protects the fix.
- The released v2.4 artifact, live index, checksum manifest, and release copies
  remain unchanged against `main`.

## Peer review round

- Reviewed the German and Arabic implementation against realistic replies rather
  than against the catalogs alone.
- Ballot parsing was exercised with ten realistic Arabic variations. Only the
  exact plain form parsed. A leading right-to-left mark, a left-to-right mark, an
  Arabic letter mark, a mark after the colon, an embedding around the line, and
  the Arabic comma separator were all refused. German passed all four of its
  variations, so the gap was specific to right-to-left text.
- The cause was that invisible direction marks are inserted by assistants and
  editors so mixed Arabic and Latin text displays correctly, and they survive
  copying. A ranking line that looked exactly right on screen therefore failed
  with nothing visible to explain why.
- Direction marks are now removed before a ballot line is matched and before
  transcript text is folded for search. Both callers work on a copy, so nothing
  stored, displayed, or exported is altered. Deliberately invalid rankings, a
  repeated label, a partial ranking, and prose are still refused.
- A browser measurement of the relay lane under right-to-left layout found every
  progress connector displaced by one station, with the first hanging off the
  edge of the page and the segment before the last station absent. The same
  measurement in English matched exactly, confirming the fault was specific to
  right-to-left. The connector is now pinned to the lane's direction rather than
  the station label's.
- Falsification was run on an isolated copy of the tracked tree. Fourteen
  deliberate breaks of the new guards were introduced across the ballot parser,
  the direction-mark helper, the locale registration, and the lane styling.
  All fourteen were caught.
- The suite is now 341 checks. Live Arabic browser checks at desktop, 390-pixel,
  and 320-pixel widths show no page-level horizontal overflow, no element
  overflowing outside a scroll container of its own, correctly aligned
  connectors, and no pointer target below 24 by 24 pixels.

## Second peer review round

- Confirmed the round label and connector fixes by measuring all 34 lane
  descendants in a browser. Inside the lane, which is pinned to a left to right
  timeline, English and Arabic now share identical centers. No other element
  inherits the label direction incorrectly.
- Added a structural guard that generalizes both lane fixes: any rule inside the
  lane that places itself on the inline axis must pin its direction back to the
  lane. Adding an unpinned logical property to the station name or to the lane
  wrapper now fails the suite.
- Measured which direction controls can actually make the visible order disagree
  with the stored order. Only an override on the ranking line does. An override
  in an earlier paragraph, an override closed before the line, and ordinary
  marks, embeddings, and isolates all render in stored order. The refusal is now
  scoped to the line, so a reply whose prose contains an override still has its
  ranking counted.
- Gave the ambiguous refusal its own explanation in all five languages, because
  the generic note told the reader to paste what they had already pasted.
- Checked whether bidirectional isolation machinery is needed. Seven Arabic
  sentences carrying two or more Latin values each were rendered in the page and
  their tokens read back in reading order. All seven read in logical order. Every
  element carrying automatic direction holds user content alone, never a
  translated sentence with interpolated values, so no isolation is warranted on
  current evidence.
- Reviewed both new catalogs for wording. German uses the informal address
  throughout, with no formal address anywhere. The six apparent formal matches
  are the pronoun meaning it or their. The thirteen German entries identical to
  English are legitimately identical words. Arabic contains no untranslated
  English outside proper nouns and technical terms.
- Falsified fifteen deliberate breaks across the ballot parser, the override
  regex boundaries, the ambiguity report, the refusal message, the catalogs, and
  the lane styling. All fifteen were caught.

## Third peer review round

- Confirmed both refinements from the previous round. The link buttons measure
  24 by 24 in every state reached: landing, first turn, mid run, guidance panel,
  shortcuts dialog, forwarded-context editor, and the preset controls. No pointer
  target anywhere in those states is now below the minimum.
- Checked the closing checkbox, whose label is the target rather than the box.
  At 390 pixels the label is 336 by 22, which is under the minimum on its own,
  but the nearest other target is 25.2 pixels away, so the spacing exception
  applies. At 320 pixels the label wraps to 42 pixels tall and clears on its own.
  The margin at 390 pixels is 1.2 pixels, which is thin enough to be worth
  knowing about.
- Found that Arabic counted nouns were ungrammatical at most counts. Arabic
  distinguishes six count categories and the catalog carried two, so the plural
  was used everywhere. Two answers read as the plural rather than the dual, and
  eleven and above read as the plural rather than the singular. Measured against
  the platform plural rules, five of eight sampled counts were wrong.
- Fixed it without touching any already reviewed language. A catalog opts in by
  supplying one of the extra forms, so English, French, Spanish, and German were
  verified byte identical at every sampled count across all five count families.
  Arabic is now correct at zero, one, two, three, ten, eleven, twenty six, and
  one hundred.
- Strengthened the catalog guarantee rather than weakening it. Every language
  still carries every English key with matching placeholders, and may now add
  only the extra count forms its own language distinguishes, all or none.
- Falsified twenty five deliberate breaks across three isolated copies covering
  the ballot ambiguity report, the pointer target rule, the navigation ordering,
  the plural machinery, the catalogs, and the parity checks.

## Fifth peer review round

- Tried to defeat both partial platform guards with seven hostile shapes: a
  selector that throws when called, a selector returning nothing, a category list
  that is not an array, an empty category list, a missing selector, a
  PluralRules that is not a constructor, and an Intl with no PluralRules at all.
  All seven opened and all seven still spelled Arabic correctly.
- Established why they hold. The four languages that declare no extra forms never
  consult a rule at all, and Arabic uses the carried rule, so the platform
  selector is not reached by any language the file ships. The registry is frozen
  after load, so no further language can be added at run time.
- Added the empty category list to the platform simulations, which was the one
  incomplete shape not yet covered.
- Replaced a test of my own that passed for the wrong reason. It registered a
  probe language after load and read the silent success as proof the validator
  had accepted it. The registry is frozen and the script is not in strict mode,
  so that registration did nothing, and under the all or none rule a live
  registration would have been refused. It now states the real invariant.
- Found and fixed an English heading in German and Arabic review packets. An
  unassigned synthesis turn carries the literal name the plan builder gave it.
  The transcript replaced it with the localized label; the packet did not.
- Demonstrated the Arabic dual case problem in real output rather than in
  principle. A packet counting two ballots reads تم حساب تصويتان, where the
  form after that verbal noun should be the oblique dual.
- Falsified seven deliberate breaks on an isolated copy. Three were not caught on
  the first attempt, and all three were weaknesses in the new tests rather than in
  the code: an assertion that matched a name appearing elsewhere in the packet, a
  missing transcript assertion, and the uncovered empty category list. All three
  were closed and all seven are now caught.
- Live Arabic browser pass at desktop, 390, and 320 pixels: right to left
  metadata correct, no horizontal page overflow, nothing overflowing outside a
  scroll container, no console errors, and no pointer target below the minimum
  apart from the closing checkbox, whose label carries the target.
