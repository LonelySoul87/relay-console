# Relay Console v2.5.0 progress

## Baseline

- Created `develop/v2.5.0` in an isolated worktree from the published v2.4.0
  merge commit `2b2a37e`.

## Language implementation checkpoint

- Added German and Arabic as complete interface and prompt languages.
- Each of the five catalogs contains the same 434 keys with identical
  placeholder sets.
- Added explicit `ltr` and `rtl` locale direction metadata. Arabic updates both
  the document language and direction without changing the selected prompt
  language.
- Converted direction-sensitive styling to logical start and end properties.
- Added automatic direction to user-entered questions, participant names,
  roles, prompts, answers, transcript text, and forwarded-context edits. Web
  addresses remain left-to-right.
- Added strict German and Arabic ballot markers without weakening the exact
  permutation validator.
- Added German and Arabic transcript export coverage and language persistence
  coverage.

## Peer review round

- Reviewed the German and Arabic implementation against realistic replies rather
  than against the catalogs alone.
- Ballot parsing was exercised with ten realistic Arabic variations. Only the
  exact plain form parsed. A leading right-to-left mark, a left-to-right mark, an
  Arabic letter mark, a mark after the colon, an embedding around the line, and
  the Arabic comma separator were all refused. German passed all four of its
  variations, so the gap was specific to right-to-left text.
- The cause was that invisible direction marks are inserted by assistants and
  editors so mixed Arabic and Latin text displays correctly, and they survive
  copying. A ranking line that looked exactly right on screen therefore failed
  with nothing visible to explain why.
- Direction marks are now removed before a ballot line is matched and before
  transcript text is folded for search. Both callers work on a copy, so nothing
  stored, displayed, or exported is altered. Deliberately invalid rankings, a
  repeated label, a partial ranking, and prose are still refused.
- A browser measurement of the relay lane under right-to-left layout found every
  progress connector displaced by one station, with the first hanging off the
  edge of the page and the segment before the last station absent. The same
  measurement in English matched exactly, confirming the fault was specific to
  right-to-left. The connector is now pinned to the lane's direction rather than
  the station label's.
- Falsification was run on an isolated copy of the tracked tree. Fourteen
  deliberate breaks of the new guards were introduced across the ballot parser,
  the direction-mark helper, the locale registration, and the lane styling.
  All fourteen were caught.
- The suite is now 341 checks. Live Arabic browser checks at desktop, 390-pixel,
  and 320-pixel widths show no page-level horizontal overflow, no element
  overflowing outside a scroll container of its own, correctly aligned
  connectors, and no pointer target below 24 by 24 pixels.

## Second peer review round

  descendants in a browser. Inside the lane, which is pinned to a left to right

  inherits the label direction incorrectly.

  with the stored order. Only an override on the ranking line does. An override

  ranking counted.

## Convergence

Four surfaces were named for this round: the rendered panels, the recovery and
import wording boundaries, the two languages set differently, and any remaining
raw identifier. Each was examined and none produced a defect. The last three
rounds have produced one product defect between them, and this round produced
none. On the technical axis this looks converged.

What remains is not technical. The Arabic dual case and the wording after قبل أن
both need a fluent reader, the screen reader session has never been performed,
and no one has touched this on a real touchscreen.

## Eighth peer review round

- Audited the feedback routing added this round. The link is the only outbound
  anchor in the file, is static, is never touched by script, carries no query
  string, and uses noopener and noreferrer, so no session content can reach
  GitHub through it. Both issue forms parse, match the schema, carry unique
  field identifiers, and mark every privacy acknowledgement as required. Blank
  issues are disabled and the security route points at a policy that exists.
- Confirmed the reported feedback target independently at 160.8 by 24 pixels in
  Arabic, and 264.3 by 24 in German.
- Found six real defects that the new contrast test did not cover, because its
  list of color pairs was written by hand and omitted the colors that were
  failing. Measured in a browser at the light palette, four colors fell below the
  4.5 to 1 minimum for normal text: the warning color at 3.77, the success color
  at 2.88, the peer-ranking color at 4.12, and the link color at 4.47 on raised
  surfaces. Two further colors were requested by the stylesheet but never defined
  anywhere, so the starter confirmation and the transcript filter controls fell
  back to inherited values.
- All six are fixed. The contrast check now derives its list of text colors from
  the stylesheet, so a color introduced later is covered automatically, and every
  color the stylesheet references must exist. Introducing a new unchecked text
  color now fails the suite.
- Two rounds of browser measurement produced apparent failures that turned out to
  be artifacts of the measurement rather than defects, and were not reported as
  such: native select options are drawn by the browser rather than the page, the
  primary buttons carry gradient backgrounds that a background walk cannot read,
  and switching the color scheme after a page has rendered leaves some
  backgrounds stale. A fresh load under each scheme shows no failures in either.

## Release acceptance decision

- Reciprocal implementation and language review is complete. Every confirmed
  finding has been fixed or explicitly resolved, and deliberate regressions
  prove the new protections can fail.
- Machine-verifiable acceptance includes the complete regression discovery run,
  five-language catalog and placeholder parity, privacy and integrity sweeps,
  desktop and narrow-browser checks, and preservation of all v2.4 surfaces.
- Native-speaker tone, screen-reader listening quality, and physical touchscreen
  feel remain useful feedback areas but are not release blockers when the needed
  person or hardware is unavailable.
- Relay Console now links to guided public issue forms for those reports. Both
  the app and forms warn users not to include private relay content. Security or
  privacy vulnerabilities remain private reports under `SECURITY.md`.
- The atomic release-candidate migration is the only remaining development step.
