# Relay Console v2.2.0 roadmap

Status: release-candidate audit complete and publication approved.

## Product goal

Make Relay Console easier to start, easier to translate, and more useful for people who already pay for ChatGPT and Claude subscriptions.

## Scope for v2.2

### 1. Reusable language packs

- Replace the fixed language list with a locale registration system.
- Validate every locale against the English catalog at startup.
- Reject missing keys and mismatched placeholders before the interface loads.
- Keep all locale data embedded in the standalone HTML file.
- Preserve separate interface and generated-instruction language choices.

### 2. Complete Spanish support

- Translate the complete interface, alerts, accessibility labels, recipes, exports, and generated instructions.
- Support both `CLASIFICACIÓN:` and the unaccented `CLASIFICACION:` in pasted ballots.
- Preserve questions, answers, participant names, and user-written roles verbatim.
- Keep English fallback for unsupported or older locale values.

### 3. ChatGPT and Claude quick starts

- Draft and improve: ChatGPT drafts, Claude critiques, ChatGPT revises, and a final synthesis follows.
- Compare independently: ChatGPT and Claude answer without seeing each other before synthesis.
- Challenge a decision: ChatGPT proposes, Claude stress-tests, the proposal is repaired, and a judge produces the verdict.
- Applying a quick start must not alter the user's question.
- Every generated participant, role, recipe, and synthesis choice remains editable.

### 4. Quality and compatibility

- Retain import compatibility with v1.x, v2.0, and v2.1 sessions.
- Keep the single-file, offline, no-API, no-backend privacy boundary.
- Test all locale keys, placeholder parity, prompt types, ballot formats, quick starts, exports, accessibility labels, and legacy fixtures.
- Run full browser smoke tests on desktop and narrow layouts.
- Keep all active product and planning files free of em dash characters.

## Release boundary

The v2.2 release-candidate audit is complete and the owner authorized publication. Do not overwrite the v2.1.0 tag or release asset. Publish through a reviewed pull request, create a new v2.2.0 tag and release, then verify the public page and download.
