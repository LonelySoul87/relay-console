# Relay Console v2.4.0 roadmap

Status: scope audit in progress on `develop/v2.4.0`.

## Product goal

Polish the complete daily workflow without weakening Relay Console's defining
boundary: one local, offline, inspectable HTML file with the user in control of
every handoff.

The release should prefer improvements that reduce mistakes, make longer relays
easier to navigate, and help a new user understand what will happen before any
session or preset data is replaced.

## Candidate priority tracks

These tracks are proposals for joint ChatGPT and Claude review. They are not all
promised until their interaction, storage, localization, and test costs are
measured.

### 1. Safer file review before import

- Preview whether a selected file is a session or preset bundle before applying
  it.
- Show version, participant count, progress, languages, preset count, naming
  collisions, and any normalization that will occur.
- Keep session replacement and preset import atomic.
- Never render imported content as HTML or execute anything from a selected file.

### 2. Better preset library management

- Consider rename, duplicate, reorder, inspect, selective export, and clearer
  bulk management.
- Preserve case-insensitive collision safety and the 50-preset ceiling.
- Keep questions, answers, prompts, and session markers outside every preset.

### 3. Faster transcript navigation

- Consider local search and filters for participant, turn type, stale answers,
  review warnings, and excluded context.
- Make long relays easier to scan without altering captured answers.
- Preserve keyboard and screen-reader access to every result and turn.

### 4. Recovery and autosave confidence

- Add a clear saved or unsaved status with the last successful local save time.
- Consider one bounded local recovery checkpoint before session replacement,
  restart, or destructive import.
- Keep recovery local, private, size-bounded, and easy to remove deliberately.

### 5. Accessibility and small-screen polish

- Audit focus movement when starting, advancing, going back, importing, and
  completing a relay.
- Consider a keyboard-shortcut reference that is discoverable without clutter.
- Verify high zoom, narrow screens, long translations, contrast, reduced motion,
  status announcements, and touch target sizes.

### 6. Export and handoff polish

- Improve filenames, visible export status, selective preset export, and
  privacy-safe troubleshooting information.
- Keep transcript and review exports linear in session size.
- Preserve the strict separation between captured answers, forwarded context,
  generated prompts, and configuration-only preset data.

### 7. Language expansion only with complete quality

- Evaluate one additional complete interface and prompt language only if key
  parity, native wording, layout review, and ballot behavior can be verified.
- Do not ship a partial translation or weaken English, French, or Spanish.
- Treat right-to-left support as a separate layout decision, not a string-only
  change.

## Explicitly out of scope

- No model APIs, backend, account, remote storage, analytics, or trackers.
- No automated reading from or writing into chatbot tabs.
- No sharing URLs containing questions, answers, prompts, or session data.
- No dependency, build step, service worker, or multi-file runtime requirement.
- No generated prompts inside preset bundles.
- No large feature whose privacy or recovery behavior cannot be tested.

## Quality boundary

- Preserve v1.x and v2.x session compatibility.
- Preserve the complete v2.3 feature set and three-language catalog parity.
- Give v2.4 a dedicated regression suite from the first scaffold commit.
- Make CI discover every matching versioned suite automatically.
- Keep active text free of the Unicode em dash character.
- Run every suite independently and in the same discovery mode used by CI.
- Complete desktop, phone-width, keyboard, and high-zoom browser checks.
- Use Claude Code for independent scope, implementation, and release-candidate
  audits.

## Release migration gate

At release-candidate time, and only after the draft passes its audit:

- Rename the draft artifact and update every draft-bound v2.4 assertion.
- Move the live `index.html` byte-identity and checksum-manifest assertions from
  v2.3 into v2.4 in the same commit.
- Extend the ordered manifest to nine release artifacts.
- Update `index.html`, `SHA256SUMS.txt`, release notes, audit, public copy, and
  the immutable artifact together.
- Re-hash the final bytes, verify the public asset after upload, and keep all
  earlier release artifacts and tags unchanged.
