# Relay Console v2.4.0 release-candidate audit

Audit date: 2026-08-31

Branch: `develop/v2.4.0`

Artifact: `relay-console-v2.4.0.html`

## Result

**PASS for peer release-candidate review.** The final naming and integrity
migration are complete. The candidate is ready for independent review before
any merge, tag, GitHub release, or public upload.

Relay Console remains one standalone HTML file with no runtime dependencies,
backend, API keys, remote assets, trackers, or programmatic network calls.

  active or saved local data.
- Added one bounded, expiring local recovery checkpoint with accurate autosave
  and storage visibility.
- Added attribute-first transcript filters and safe navigation among reached
  lane stations.
- Added preset inspection, rename, duplicate, selected export, portable dated
  filenames, and visible export confirmations.
- Hardened ballot truth, recovery identity and expiry, preset selection and
  storage failures, focus routing, live announcements, and keyboard behavior.
- Preserved English, French, and Spanish catalog parity, older session imports,
  the offline privacy boundary, and the single-file runtime.

The candidate migration was performed only after that reciprocal cycle
converged. The v2.3 suite lost current-release integrity ownership in the same
change that v2.4 gained it.

The final artifact was served from a clean local HTTP origin after migration.
At 390 by 844 CSS pixels, the setup page fit in English, French, and Spanish
with no horizontal overflow. A clean Draft and improve relay started, saved and
advanced through Ctrl+Enter, preserved the captured answer, and reported the

At 320 by 700 CSS pixels, the relay still had no horizontal overflow. The
shortcut dialog fit without internal scrolling, moved focus to its heading,
and returned focus to the trigger on Escape. The updated landing page also fit

Earlier reciprocal passes additionally covered import review; simultaneous
resume and recovery banners; preset management; transcript filters; mouse and

covered directly by the regression suite.

Not claimed as completed:

- A listening session with NVDA or VoiceOver to judge announcement sequence by

These are manual acceptance follow-ups, not concealed automated passes. The
known touch risk is limited to where focus lands after navigation, not whether
the turn changes or whether the answer remains reachable.

### Integrity falsification, seven cases

Every case run on an isolated copy of the tracked tree. All seven now fail as
they should: a one-byte drift in `index.html`, a falsified v2.4 digest, a
falsified historical digest, a missing ninth entry, a reordered manifest, a
tampered release artifact, and a CRLF rewrite of the manifest.

### The gap that was closed

The CRLF case passed silently before this audit. The manifest parser splits on
`/\r?\n/`, so a line-ending conversion was invisible even though
`.gitattributes` pins the file to LF and `docs/checksum-integrity-fix.md`
records an incident where exactly that conversion produced three wrong
checksums. The manifest is published as a release attachment and users verify
downloads against it, so the working bytes now get asserted directly: no
carriage returns, single trailing newline.
